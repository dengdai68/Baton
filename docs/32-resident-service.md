# ADR：本机常驻服务与公网访问安全

## 背景

手机要在 Mac 关闭 Baton 后仍能连接本机工作空间；用户计划把工作空间端口开放到公网（HTTPS 与网络层由用户负责）。原架构里业务服务只是 Electron 应用的子进程，应用退出即停止；手机网关按「已配对设备 = 实例所有者」放行大部分接口。

## 决策

### 1. 常驻服务 = launchd 用户代理托管的监督进程

- `apps/electron/daemon.mjs` 由 launchd 以用户 LaunchAgent（`~/Library/LaunchAgents/com.baton.daemon.plist`，非标准配置根追加根目录哈希后缀）运行：`RunAtLoad`（登录即启动）、`KeepAlive.SuccessfulExit=false`（异常退出后重启，正常停止不重启）、`ThrottleInterval=30`。
- 程序是应用自己的可执行文件（`ELECTRON_RUN_AS_NODE=1`），保持与 Baton.app 相同的代码身份，因此沿用用户授予 Baton 的文件访问权限（外接卷、完全磁盘访问）。本机安装需使用稳定签名身份，否则每次重装 macOS 都会收回授权。
- 监督进程像桌面应用一样拥有业务服务子进程：相同环境（登录 Shell 环境 + 桌面存储路径，不设 `BATON_WORKSPACE_DAEMON`，保持桌面语义）、相同 IPC 协议（`baton-ready`、`baton-notification`、`baton-update-prepare/readiness/release`、`baton-storage-restart`）。`server/index.mjs` 仍要求父进程 IPC，父进程断开即退出。
- 配置根中的私有 Unix socket `daemon.sock`（0600，仅同一用户）向 Mac 应用提供：状态（含首次设置用的 bootstrap 令牌）、通知订阅、空闲预约（更新前确认没有执行中的任务、沟通或保存）。数据目录更换由监督进程执行（停止、搬运、重启；失败保留原位置）。
- 已保存的数据位置不可访问（例如外接盘未连接）时监督进程拒绝启动，绝不创建空实例；launchd 稍后重试。
- 代理标签由配置根的规范路径（解析符号链接）派生，首次启动与之后启动一致。`launchctl bootout` 是异步的：重新加载或移除代理时等待原进程退出后再 bootstrap 或返回，否则同名代理会被跳过而不再运行。
- 应用侧：`设置 → 工作空间 → 本机服务 → 常驻后台运行`。标准实例（打包应用的 `~/.baton`）默认开启；其他配置根和测试默认关闭（`BATON_DESKTOP_RESIDENT=0/1` 可显式指定）。两种模式共享同一运行中的服务。开关只安装或移除下次登录的 LaunchAgent 定义，保留进程、端口、登录会话和实时连接。关闭常驻时，最后一个桌面宿主离开后服务停止。应用更新不重启常驻服务；应用连接时比较构建标识（版本号 + 可执行文件修改时间，签名会改写可执行文件，因此同版本号的本机重装也能识别），服务仍运行旧构建就在空闲时重启它（忙碌时 15 分钟后再试）。

### 2. 工作空间账号与设备会话

- 客户端通过 HTTPS 地址登录。Mac 托管的服务验证本机管理员账号，手机使用设备令牌，其他 Mac 使用 HTTPS 登录会话。
- `mobile` 范围只读配置：插件、MCP、Git 凭据、Runtime 与员工/团队/工作流/角色目录的写操作在网关拒绝（读取 MCP 工具列表除外）；任务、沟通与自动化照常可写。
- 设备会话闲置 30 天失效，使用即续期；设备列表记录登录时间、最近访问时间与地址，可随时撤销。

## 公网暴露的安全模型（软件层）

**前提**：任何能创建任务或发起沟通的已配对设备，都能让数字员工以 Mac 用户权限执行操作（Runtime bypass 不是沙箱）。因此「设备令牌 ≈ 主机账户权限」，安全的核心是认证强度、可撤销性与可见性。

| 方面 | 措施 |
| --- | --- |
| 认证 | 设备令牌与配对码均为 256 位随机数，只存 SHA-256 摘要；云端密码用 scrypt；Cookie 为 `__Host-`、HttpOnly、Secure、SameSite=Strict；Cookie 写请求要求同源 Origin 与 JSON。 |
| 登录限流 | 来源 IP 在 10 分钟内失败 20 次后暂停登录 10 分钟。账号与来源 IP 组合在 24 小时内失败 20 次后持久封禁 24 小时。代理来源必须写入 `trustedProxyAddresses` 才会采信其转发的客户端地址。详见 [工作空间服务](31-workspace-service.md)。 |
| 授权 | 网关默认拒绝，仅转发白名单路由；数据重置、更换数据目录、本机维护设置只能在 Mac 上操作；手机范围只读配置。 |
| 可见性与审计 | 诊断日志记录登录、撤销、首次认证失败与封禁（不含令牌）；Mac 设备列表显示最近访问时间与地址。 |
| 资源滥用 | 每台设备最多 8 条实时事件流；网关最多 256 个并发连接；请求头 15 秒、请求 300 秒超时；JSON 1 MiB、附件 20 MiB 上限。 |
| 信息泄露 | 远程请求的非预期内部错误只返回「请求处理失败」，细节只写入本机日志；响应带 HSTS、CSP、`X-Frame-Options: DENY`、COOP/CORP、nosniff、no-referrer、no-store。Host 头必须等于配置的 origin。 |
| 本机隔离 | 桌面 API 只监听 127.0.0.1；Mac 宿主接口只暴露给本机 `http://127.0.0.1` 页面，远程页面拿不到；常驻服务 socket 与连接文件为 0600。 |
| 依赖 | 生产依赖 `npm audit --omit=dev` 为 0 已知漏洞（MCP SDK 升级到 1.32.2）。 |

## 加密：哪些有必要

- **传输**：必须 HTTPS（由用户的证书或反向代理负责）。手机对自签证书做 SHA-256 证书固定；使用公共 CA 证书时按系统信任。
- **凭据**：令牌与密码只存摘要，无需再加密；手机令牌存 iOS 钥匙串。
- **业务数据（SQLite、任务文件、执行记录）**：不做应用层加密。密钥只能存在同一台 Mac 上，挡不住已获得用户会话的攻击者，却增加损坏与恢复风险。应使用系统级加密：**开启 FileVault**，并把存放数据的外接卷设为 **APFS 加密卷**。当前这台 Mac 两者都未开启，且执行记录可能包含提示词与工具输出中的敏感片段，建议开启。
- **配置中的机密**（Git Token、MCP 环境变量）：以 0600 私有文件保存，接口只返回脱敏结果；员工运行时需要明文，钥匙串收益有限，依赖系统级加密即可。

## 不做

- 不使用系统级 LaunchDaemon（root、开机即启动）：员工运行的 CLI 依赖用户的登录态与钥匙串，必须在用户会话中运行。
- 不做按任务或角色的操作权限；不把 Runtime bypass 当成沙箱。
- 网络层（端口映射、反向代理、证书签发、WAF）由部署者负责。
