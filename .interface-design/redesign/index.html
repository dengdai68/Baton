AgentForge 客户端界面重设计

基于隔离客户端实测的 98 张截图（两套主题、1440 与 760 两种宽度）和样式源码分析，给出问题清单、可复用的设计系统、三种风格方向，以及覆盖全部核心页面的可交互 HTML 设计稿。业务逻辑、HTTP / CLI 契约与执行规则均不变。

22个问题 · 4 个 P0
16个设计页 · 另含错误、空态等状态
3 × 2种风格 × 浅色 / 深色
521 → 0组件中的颜色字面量

最大的三个问题

  1. 「需要我处理」没有一等入口，澄清、验收、中断混在列表里靠小标签区分。
  2. 视觉权重倒置：每行最醒目的是红色「删除任务」，真正的下一步反而没有入口。
  3. 样式没有收敛成系统：521 个颜色值、27 种字号、两层 CSS 互相覆盖。

三项核心改动

  1. 以「待我处理」为中心重组信息架构，任务按「需要谁行动」分组，每行只有一个下一步。
  2. 三层 Token + 统一组件 + 状态体系，组件中不再出现字面量。
  3. 桌面化外壳：一体化标题栏、⌘K 命令面板、深色模式和明确的窗口缩放规则。

A · 石墨（2026-11-13 改选，替代 B · 纸张），提供浅色、深色与跟随系统；规范见 .interface-design/system.md。其余待定事项按方案执行；「可用」状态按你的反馈改为不显示，绿点只表示执行中。

P0

阻碍核心流程

用户找不到该做的事，或容易做错事
01「需要我处理」没有一等入口
现象
侧栏「任务中心 4 待你处理」只是计数，点进去是全量列表；等待澄清、待验收、错误中断与草稿、已完成混排，只靠 11px 状态标签区分。总览页对新用户默认隐藏。
影响
人类决策是 AgentForge 的关键闭环（澄清→继续，验收→完成），现在要逐行扫读才能找到。
建议
新增「待我处理」视图（现有数据的客户端聚合）；任务列表按「需要谁行动」分组。待我处理 ↗ 任务 ↗
02行操作与状态脱节，危险操作最显眼
现象
红色「删除任务」在多行重复，是列表里最醒目的元素；而「去澄清 / 去验收 / 查看恢复选项」在列表里没有入口——源码 taskActionLabel() 已有这些文案却没有用上。按钮数量随状态增减，操作列参差不齐；760px 时换成两行，行高翻倍。
影响
误删风险高；最常用的操作需要先进入任务再找。
建议
每行只露出一个「下一步」，其余收进 ⋯ 菜单，删除二次确认。此项与既有「操作列直接展示、不使用更多菜单」的决定不同，见 D3。
03任务工作区里，待回答的问题被稀释
现象
同一个问题同时出现在顶部横幅、消息卡片和「消息用途」下拉（整句截断成两行）三处；输入区约占屏高 30%；「全部」筛选用主色实心按钮，和真正的主操作争夺注意力；协作页签上「1 待你回复」是深琥珀实心块，与其他徽标风格不一致。
影响
用户需要在三处之间确认「我在回答哪个问题」；视觉焦点分散。
建议
问题卡片内直接「回复」，输入框顶部显示可移除的回复上下文；筛选改为分段控件。任务工作区 ↗
04状态颜色语义冲突
现象
品牌蓝同时表示主按钮、选中、员工「可用」、运行时「支持」和任务「进行中」；需要人类行动的「待你验收」却是灰色，与「草稿」「已暂停」同色；状态只有颜色和文字，没有形状区分。
影响
无法一眼区分「正常」「进行中」「需要我」；色弱用户只能读文字。
建议
5 类语义（进行中 / 需要你 / 完成 / 失败 / 中性）+ 形状图标 + 文字三重编码；「可用」作为默认状态保持安静。状态体系 ↗

看起来像多个产品拼在一起
05样式没有收敛成系统
现象

06两套会话视觉语言
现象
任务协作：人类气泡、彩色类型标签、等宽时间戳；沟通：竖线姓名、下划线分隔、无气泡、外层再套卡片容器。同一产品的两个对话面板读起来像两个应用。

07字体使用混乱，没有页面级标题
现象
等宽字体被用于时间戳（2026/11/11 00:56:10）和团队成员姓名标签；页面只有顶栏 13px 页名，与正文同级；弹窗标题 18px / 700、设置标题 15px，层级跳跃。
建议
7 级字阶；等宽只用于代码、路径、ID、Cron；时间用相对时间，悬停看精确时间。
08目录页结构各不相同
现象
员工是高卡片（约 285px，大段留白，「对话 / 编辑 / 删除」重复 8 次）；角色卡片的按钮随描述行数上下错位；团队列表裸露英文状态 active；工作流列表按钮数量不同导致不对齐；插件 / MCP 只有一张卡片和大片空白。
建议
只保留两种目录模板：列表行与卡片网格；员工、插件、MCP 共用一张卡片，点击在右侧抽屉看详情，操作常驻卡片底部。员工 ↗ 插件 ↗
09图标与术语混用
现象
按钮里用字形充当图标（Ⅱ 暂停、■ 终止 Run、↓ 最新、＋ 创建、↗）；「终止 Run」「CHANGE」「1 条 Trace」等内部英文术语直接出现在界面上；删除确认列出 Task、Run、Trace、Artifact、Decision、Event。
建议
一套 SVG 图标；面向用户的术语表，确认文案只讲后果。术语表 →
10表单弹窗缺少结构
现象
创建员工是一条 9 个字段的长滚动表单，最重要的「系统提示词」夹在中间；新建任务把完整的工作目录绝对路径以小字显示；三个底部按钮视觉权重接近。
建议
员工编辑分为「基本信息 / 职责与提示词 / 运行配置 / 工具」并加左侧锚点；路径缩写；按钮按幽灵 / 次要 / 主要分级。员工编辑 ↗
11设置页信息过载，保存方式不一
现象
几乎每段说明都做成灰底框；运行时 9 行重复「CLI 默认模型 · 默认思考等级 · N 位员工」；外观即时保存，而常规和插件更新要点「保存」，禁用态是浅蓝色，看起来像可点击。
建议
分组卡片 + 行布局；只显示非默认值；即时生效并给出「已保存」反馈。设置 ↗
12两套主题差异过小
现象
暖白与极简在同一页面的截图中几乎无法分辨（侧栏底色 #f3f2fa 与 #f0f4fd），却需要维护两套覆盖。
建议

设计原则

1 · 内容优先，界面退后

用边线和留白组织信息；页面内容不用阴影、渐变和装饰色块，只有浮层有阴影。

2 · 默认安静，异常发声

只有需要人行动的状态（澄清、验收、中断）才用强调色；「可用」「空闲」这类常态不着色。

3 · 一个区域一个主操作

主按钮只表示「下一步」；筛选与切换用分段控件；危险操作放进菜单并二次确认。

4 · 键盘与鼠标等价

所有操作都能用键盘完成；⌘K 是全局入口；焦点始终可见，弹窗关闭后焦点回到触发处。

5 · 像原生 Mac 应用

一体化标题栏、系统字体、可拖动区域、只有内容区滚动，尊重深色模式与减少动画偏好。

6 · 呈现事实，不替用户判断

沿用产品边界：协作焦点、状态颜色只呈现已记录的协调事实，不暗示业务结果已通过，最终完成由人确认。

预览风格

1 · 任务中心（基准页）

  1. 按「需要谁行动」分组：待我处理（澄清、验收、中断）置顶，其后进行中、暂停、草稿、完成；原先 6 种状态平铺，只能逐行读小标签。
  2. 每行一个下一步：「去澄清 / 去验收 / 查看恢复选项」直接使用现有 taskActionLabel 文案；删除、归档、编辑收进 ⋯ 菜单（D3）。
  3. 状态三重编码：形状图标 + 颜色 + 文字；「待你验收」从灰色改为琥珀，与草稿可区分。
  4. 筛选改为视图标签：全部 / 待我处理 / 进行中 / 草稿 / 已完成 / 归档，替代两个下拉加「搜索 / 重置」按钮，筛选即时生效。
  5. 补充进度与成员：当前步骤与执行人（来自已有的协作焦点）、成员头像叠放；不新增后端字段。
  6. 标题栏一体化：名称、计数、视图切换与主操作在 48px 内，去掉重复页名的 44px 顶栏。
  7. 列表 / 看板：看板只是同一数据的另一种排列，不提供拖拽改状态——状态仍由协调与人类确认推进。
  8. 键盘：/ 聚焦筛选、J/K 移动、↵ 打开、C 新建；⌘K 全局搜索任务。

2 · 任务工作区 · 协作

  1. 标题栏集中：面包屑 + 状态胶囊 + 暂停；「Ⅱ 暂停」「■ 终止 Run」字形按钮改为图标按钮，终止运行收进 ⋯。
  2. 问题就地回答：横幅、问题卡片、「消息用途」下拉三处合一，输入框顶部显示可移除的回复上下文。
  3. 记录区自适应宽度：不设最大宽度，左右留白随窗口变化；记录之间很轻的分隔线；人类靠右气泡、员工靠左（沿用既有规则），去掉等宽时间戳。
  4. 消息工具悬停出现：「本轮控制台」、复制在悬停时浮现，不在每条消息下常驻。
  5. 详情栏重组：概要 → 协作焦点 → 成员 → 描述 → 工作目录；协作焦点注明「依据交接记录呈现，不代表平台判定」。
  6. 沿用详情栏规则：协作默认展开，文件与控制台默认收起，各页签记住手动选择；≤1180px 变浮层，⌘I 切换。成员行保留控制台按钮，绿点表示执行中。
  7. 控制台按执行分组：每次执行一张卡片（耗时、状态），读取 / 命令 / 写入 / 思考用图标区分，失败行就地标红。
  8. 文件页：当前文件 / 变更用分段控件；文件头显示路径、写入者与下载；行内 / 左右、仅差异 / 完整文件切换保留。

3 · 沟通 · 群聊

  1. 与任务协作共用消息组件：同一产品只有一套对话语言与输入框。
  2. 去掉外层卡片容器：三栏贴边，减少嵌套边框，与其他页面的外壳一致。
  3. 会话列表：群聊用叠放头像，未读用蓝色计数，可搜索会话。
  4. 控制台入口在成员栏：每位成员一个控制台按钮，绿点表示正在执行；控制台只显示所选成员，不用页签切换；私聊入口仍在标题栏（沿用现有规则）。窄窗口成员栏改为浮层，输入框始终在首屏。

4 · 数字员工

  1. 卡片高度约 285 → 170px：简介固定 2 行，去掉空白描述区。
  2. 操作常驻底部：「对话」+ ⋯ 固定在卡片底部，不在悬停时覆盖内容；删除进菜单。
  3. 状态安静化：「可用」不显示，执行中显示绿点，已停用显示灰色标签（D4 按反馈调整）。
  4. 编辑分区：基本信息 / 职责与提示词 / 运行配置 / 工具，左侧锚点；点击卡片打开只读抽屉，不离开列表。

5 · 设置 · 运行时

  1. 分组卡片 + 行布局：标签与说明在左、控件在右；说明不再做成灰底框。
  2. 只显示非默认值：「opus · 思考 High」；未安装的运行时锁定并说明原因。
  3. 即时生效：开关与选项直接保存并显示「已保存」（D7）；需要提交的表单才保留按钮。
  4. 危险操作独立区域：「清除所有数据」放入红色边框区，仍需密码与输入确认。

6 · 新建任务

  1. 文档式输入：标题与描述去掉边框，内容优先（沿用既有方向）。
  2. 成员与工作流同排：沿用框内多选与 ★ 经理指派。
  3. 路径缩写：工作目录显示为 ~/AgentForge/tasks。
  4. 按钮分级：取消（幽灵）/ 保存草稿（次）/ 保存并开始（主，⌘↵）；Enter 仍为保存草稿。

7 · 窄窗口 760px

  1. 图标侧栏：徽标变为圆点；标题栏保持单行，面包屑截断、状态胶囊保留。
  2. 首屏可回复：详情栏变为浮层（⌘I），回复上下文与输入框始终在首屏。
